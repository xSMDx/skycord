# v0.22.0 (draft, not released) — Files in chat, and Skycord for Linux

A draft for v0.22.0, in the voice of the landing page's `RELEASES` list (`landing/content.js`). Each
line is tagged as it is there: **add**, **imp** (improved) or **fix**. It is three tags (see
`docs/RELEASING.md` and `docs/superpowers/plans/2026-11-09-v0.22.0-release.md`): `v0.22.0` for the
server and web client, `desktop-v0.22.0` for the Windows and Linux apps, and `android-v0.22.0` for
the Android app (still a beta), in that order. Review every line against the merged `main` before
tagging; lines for PRs that don't make it come out.

Title: **Files in chat, and Skycord for Linux**.

## Added

- **add** — **Send files.** Attach photos, videos and files to a message in DMs, groups and
  channels: pick them, paste them or drop them, up to 10 at a time, with or without text. Each one
  starts uploading as soon as you add it, and if one can't go, it says why under its tile before
  you send. In a server, it follows the **Attach files** permission, which is now enforced.
- **add** — **Previews instead of links.** Photos and videos show in the message, several sharing
  one box, and open in a large view with download and arrows. Other files show as a card with
  their name, type and size, and a download button. GIFs play in place, including GIF links in the
  middle of a sentence. Reduced motion and "tap to play" still hold them still until you ask.
  Previews in the conversation list, replies, pins, search and notifications say "Sent a photo",
  "GIF" or the file's name, never a raw link.
- **add** — **Skycord for Linux.** The desktop app now comes for Linux as an AppImage, which runs
  on a stock Ubuntu with nothing extra installed, and as a `.deb`. It has its own launcher entry
  and icon, an unread count where the desktop shows one, and the same custom title bar. Sharing
  one app's sound, or the whole computer's, isn't available on Linux yet, and the share picker
  says so.
- **add** — **Files on Android** (beta). Download saves a file to the phone's Downloads, and a
  message that is only files is notified as "Sent a photo", "GIF" or the file's name instead of
  "New message".

## Fixed

- **fix** — **Calls on a self-hosted server dropped and re-joined every 15 seconds.** The bundled
  voice server is now LiveKit 1.13.11. **If you run your own LiveKit, it needs 1.9.1 or newer.**
- **fix** — **Your own full profile showed only some of its parts.** It now fills its card, banner
  and status line included, as other people's profiles do.

## Notes for people who host their own server

- **Uploads are scanned when a scanner is set.** Chat files go through the same ClamAV scanner as
  music when `CLAMD_HOST` is set (the scanner compose file now covers chat uploads too). With a
  scanner set but unreachable, uploads are refused rather than let through unscanned.
- **Uploads are capped at 25 MB per file** (`ATTACH_MAX_BYTES`), the music limit. Your reverse
  proxy must allow bodies that size; the installer's Caddy already does.
- **Files are stored in your database** (GridFS), not on disk. A file deleted with its message goes
  with it, and uploads nobody sent are cleared after a day.
- **Links to files work without signing in**, so images can load in the app. Each link carries a
  long random key and can't be guessed.
