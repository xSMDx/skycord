# Windows desktop app v0.20.0 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** an Electron shell that asks which instance to use, then opens that server's own web client, updates itself, and grants the page only what it needs.

**Architecture:** thin shell. No bundled client — the window loads `https://<instance>/` and the existing web client works unchanged, because it already addresses the API and socket relatively. A preload bridge is the only surface the page gains.

**Tech Stack:** Electron (latest stable at install), TypeScript, electron-builder (NSIS), electron-updater, Vitest for the pure modules.

**Source:** `docs/superpowers/specs/2026-09-21-desktop-app-design.md` (owner decisions, 2026-09-21).

## Global Constraints

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Nothing else reaches the page.
- The window navigates only within the chosen instance's origin. Everything else opens in the system browser, and only `http:`/`https:`.
- Microphone, camera and notification permissions are granted to the chosen origin only; every other permission request is refused.
- No secret in the repo. The release workflow reads `DESKTOP_RELEASES_TOKEN` from repo secrets.
- The web client gains exactly one thing: a "Switch server" button that appears only when the bridge exists.
- Windows only in v0.20.0. Unsigned.

### Task 1: The shell that opens a window

**Files:** create `desktop/package.json`, `desktop/tsconfig.json`, `desktop/src/main.ts`, `desktop/.gitignore`.

- [ ] Install in `desktop/`: `electron`, `electron-updater`, and dev `typescript`, `electron-builder`, `@types/node`. Use `npm install --replace-registry-host=always` (the lockfile's mirror answers 402 on this machine).
- [ ] `main.ts`: create a `BrowserWindow` (1200×800, `show: false`, show on `ready-to-show`), `webPreferences: { contextIsolation: true, nodeIntegration: false, sandbox: true, preload }`. Quit on all windows closed (Windows).
- [ ] Scripts: `"dev": "tsc && electron ."`, `"build": "tsc"`.
- [ ] Verify: `npm --prefix desktop run dev` opens an empty window. Commit: `feat(desktop): an Electron shell that opens a window`.

### Task 2: Reading an address

**Files:** create `desktop/src/instanceAddress.ts` and its test.

**Produces:** `normaliseAddress(input: string): string | null`, `type Lookup = { ok: true; profile: InstanceProfile; origin: string } | { ok: false; reason: string }`, `lookupInstance(input, fetchImpl?): Promise<Lookup>`.

- [ ] Test first. `normaliseAddress`: `chat.example.com` → `https://chat.example.com`; keeps an explicit `http://`; strips a path, query and trailing slash; rejects empty, spaces, and anything that is not `http`/`https` (`javascript:`, `file:`). `lookupInstance`: a 200 with `software: "skycord"` succeeds and returns the origin; a 200 whose body is not a Skycord profile, a 404, a 500 and a network error each fail with a plain reason naming what happened — never a raw stack.
- [ ] Implement. Fetch `<origin>/instance` with a timeout (5s, `AbortSignal.timeout`). Inject `fetchImpl` so the tests never hit the network.
- [ ] Verify: `npx vitest run desktop/`. Commit: `feat(desktop): read and check an instance address`.

### Task 3: The picker, and remembering the choice

**Files:** create `desktop/src/store.ts`, `desktop/src/picker/index.html`, `picker.css`, `picker.ts`. Modify `main.ts`.

- [ ] `store.ts`: read/write `{ instanceOrigin: string }` as JSON in `app.getPath('userData')`. Tolerate a missing or corrupt file by returning `{}`.
- [ ] The picker page: two choices — **skycord.xyz** and **your own server** with an address field. On submit, the main process does the lookup (over IPC, so the page never makes the request) and returns the profile; the page shows the instance's name, icon and operator with a **Continue** button, or the failure reason. Style it with the app's own tokens — copy the handful needed rather than importing the web stylesheet.
- [ ] `main.ts`: on launch, load the picker when nothing is stored, otherwise go straight to the instance.
- [ ] Verify by running it: pick skycord.xyz, relaunch, it goes straight there. Commit: `feat(desktop): choose an instance, and remember it`.

### Task 4: Loading the instance, and the rules around it

**Files:** modify `desktop/src/main.ts`. Create `desktop/src/displayMedia.ts`.

- [ ] Load `<origin>/`. On `will-navigate` and `setWindowOpenHandler`, allow the chosen origin and send everything else to `shell.openExternal` — only if the URL is `http:` or `https:`.
- [ ] `session.setPermissionRequestHandler`: allow `media` and `notifications` for the chosen origin; deny everything else.
- [ ] `displayMedia.ts`: `session.setDisplayMediaRequestHandler` listing `desktopCapturer.getSources({ types: ['screen', 'window'], fetchWindowIcons: true })` in a small always-on-top window; resolve with the chosen source, or cancel. Minimal on purpose — roadmap 5.6 replaces it.
- [ ] Verify by running it: sign in, join a call, share a screen; an external link opens in the browser and not in the app. Commit: `feat(desktop): load the instance, and nothing else`.

### Task 5: Plain-HTTP instances

**Files:** modify `desktop/src/main.ts`.

- [ ] Before `app.whenReady()`, if the stored origin is `http:`, `app.commandLine.appendSwitch('unsafely-treat-insecure-origin-as-secure', origin)` and `appendSwitch('disable-site-isolation-trials')`.
- [ ] Choosing an `http:` instance in the picker saves it and calls `app.relaunch(); app.exit(0)`, with the picker saying the app will restart once.
- [ ] Verify against a LAN instance on `http://`: after the relaunch, the microphone works. Commit: `feat(desktop): a plain-HTTP instance still gets a microphone`.

### Task 6: The bridge, and one button

**Files:** create `desktop/src/preload.ts`. Modify `main.ts`, `src/components/settings/AboutInstancePage.vue`, and its test.

**Produces:** `window.skycordDesktop = { version: string; platform: string; changeInstance(): void }`.

- [ ] `contextBridge.exposeInMainWorld`. `changeInstance()` clears the stored origin and loads the picker.
- [ ] `AboutInstancePage.vue`: a "Switch server" row, rendered only when `window.skycordDesktop` exists, calling `changeInstance()`. A test asserts it is absent without the bridge and present with it.
- [ ] Verify: `npx vitest run src/ desktop/` and `npm run typecheck`. Commit: `feat(desktop): switch server from Settings`.

### Task 7: Installer and updates

**Files:** create `desktop/electron-builder.yml`. Modify `desktop/package.json`, `main.ts`.

- [ ] `electron-builder.yml`: `appId`, product name Skycord, `target: nsis`, `oneClick: false`, `perMachine: false`, and `publish: { provider: github, owner: xSMDx, repo: skycord-desktop-releases }`.
- [ ] `main.ts`: `autoUpdater.checkForUpdatesAndNotify()` on launch and every 6 hours. On `update-downloaded`, a dialog offering "Restart now" or "Later".
- [ ] Verify: `npm --prefix desktop run dist` produces an installer; install it and it runs. Commit: `build(desktop): an installer that updates itself`.

### Task 8: The release workflow

**Files:** create `.github/workflows/desktop-release.yml`.

- [ ] On a `desktop-v*` tag: `windows-latest`, checkout, Node 22, install, `electron-builder --publish always` with `GH_TOKEN: ${{ secrets.DESKTOP_RELEASES_TOKEN }}`.
- [ ] Add `desktop/` to the existing CI test job so its unit tests run on every push.
- [ ] Verify by tagging `desktop-v0.20.0-rc.1` and watching a release appear in the releases repo. Commit: `ci(desktop): build and publish on a tag`.

### Task 9: See it (owner)

- [ ] Install from the published installer. Pick skycord.xyz; sign in; call; share a screen.
- [ ] "Switch server" → pick a self-hosted instance → the app opens that server's client.
- [ ] An `http:` LAN instance: one restart, then voice works.
- [ ] Publish an rc.2 and confirm the running app offers the update and restarts into it.

## Self-review

**Spec coverage.** Picker → 2, 3. Server's own client → 4. Bridge and Switch server → 6. Updates → 7, 8. Security rules → 4. HTTP instances → 5. Minimal screen chooser → 4. Out-of-scope items stay out.

**Risk worth naming.** The shell is only as good as the origin rules in Task 4; they are what stops a hostile page in a self-hosted instance reaching the machine. Task 4 is the one to review hardest.

**Unknowable until run.** Electron's exact version, and whether `unsafely-treat-insecure-origin-as-secure` still covers `getUserMedia` in that version — Task 5 verifies it against a real LAN instance rather than assuming.
